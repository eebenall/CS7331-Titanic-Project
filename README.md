# CS7331-Titanic-Project

The objective of this project is to apply predictive analytics and data mining techniques to the Titanic passenger dataset to identify key factors that influenced passenger survival during the Titanic disaster. By analyzing passenger attributes such as age, gender, passenger class, fare, and family size, we aim to build classification models that can predict whether a passenger survived. Several data mining algorithms, including Naïve Bayes, K-Nearest Neighbors (KNN), Support Vector Machines (SVM), and Random Forest, will be implemented and compared to evaluate their predictive performance.

In addition to building predictive models, this project will examine how data quality and preprocessing methods impact model performance. The dataset contains missing values in variables such as Age and Cabin, which may influence prediction accuracy. To address this, we will test different data imputation strategies to determine which approach leads to improved model performance.

Furthermore, we will explore data mining techniques to enhance the dataset. For example, passenger names contain titles such as Mr., Mrs., Miss, and Master, which may provide insights into social status or passenger demographics. We will extract these titles and evaluate whether they improve predictive accuracy. Through this analysis, we aim to better understand how demographic, socioeconomic, and data preprocessing factors influence survival outcomes in the Titanic dataset.

## Jeena's Work: Feature Engineering & Socioeconomic Impact

### Data mining workflow

`feature_engineering.py` follows the main data mining lifecycle steps:

1. Load and audit the Titanic training data
2. Engineer title-based socioeconomic features
3. Clean missing values and encode categorical columns
4. Build base, socioeconomic, and all-feature datasets
5. Tune model parameters using GridSearchCV
6. Evaluate models with accuracy, precision, recall, F1, reports, and confusion matrices
7. Save plots for comparison and interpretation

### What `feature_engineering.py` does

- Extracts titles (Mr, Mrs, Miss, Master, etc.) from the Name column and groups rare ones into "Rare"
- Fills missing Age with the median age for each title group instead of just the overall median
- Fills missing Embarked with the most common value, drops Cabin since ~80% is missing
- One-hot encodes Title and Embarked (nominal categoricals); label-encodes Sex (binary)
- Scaling is done inside a `Pipeline` per feature set so no data leaks into cross-validation
- Stratified 80/20 train/test split to preserve class balance (38% survivors)
- Compares 3 feature sets:
  - **Base**: just Age + Sex
  - **Socioeconomic**: Age + Sex + Pclass + Fare + Title
  - **All**: every available feature
- Tunes each model (NB, KNN, SVM, RF) with GridSearchCV using 5-fold CV on F1
- Outputs accuracy, F1, precision, recall, confusion matrices, classification reports, and 4 plots

### Results

| Model | Base Acc | Socio Acc | Gain |
|-------|:---:|:---:|:---:|
| Naive Bayes | 77.7% | 78.2% | +0.6% |
| KNN | 76.0% | 82.7% | +6.7% |
| SVM | 77.1% | 81.6% | +4.5% |
| Random Forest | 73.7% | 83.8% | +10.1% |

Random Forest did the best overall — 83.8% accuracy and 0.785 F1 with socioeconomic features. Adding Pclass, Fare, and Title on top of Age/Sex gave a 5–10% boost for most models.

Note: Naive Bayes barely moved (+0.6%) — its feature independence assumption means adding correlated features like Pclass and Fare provides little benefit.

## Everett's Work: SVM & Random Forest Analysis

### Overview

Two independent classification scripts implementing Support Vector Machine and Random Forest models to predict Titanic passenger survival. Both scripts share an identical preprocessing pipeline to ensure fair model comparison, and each is fully self-contained — running either script requires only `train.csv` in the working directory.

### Shared Preprocessing Pipeline

Both scripts apply the same preprocessing steps before modeling:

- **Age** — Title-group median imputation (Master=3.5, Mr=30, Mrs=35, Miss=21, Officer=50) rather than a global median, preserving demographic distinctions between passenger subgroups
- **Cabin** — Converted from 77.1% missing into two engineered features: `HasCabin` (binary flag) and `Deck` (first letter of cabin, `U` for unknown)
- **Fare** — Pclass-group median fill for the one missing value, then capped at the 99th percentile (£249.01) to remove extreme outliers
- **Embarked** — Mode fill (Southampton) for two missing values
- **Title** — Extracted from passenger names and grouped into six categories: Mr, Mrs, Miss, Master, Officer, Royalty
- **FamilyBand** — Passengers bucketed into Alone (size=1), Small (2–4), and Large (5+) replacing raw FamilySize and IsAlone
- **Stratified 80/20 train/test split** — Preserves the 38.3% survival rate in both partitions

### `titanic_svm.py`

**Model:** Support Vector Machine with RBF kernel  
**Best configuration:** `C=5`, `gamma=0.05`, `class_weight=balanced`  
**Selection method:** 5-fold GridSearchCV across linear, RBF, and polynomial kernel sub-grids

**Key design decisions:**
- Fare receives a `log1p` transform inside a dedicated sub-pipeline before StandardScaler to compress right skew — unique to SVM since it is distance-based
- `class_weight=balanced` enforced across all kernel sub-grids to address the 38/62% survivor imbalance
- Three iterative versions developed: v1 (uncleaned baseline, failed to converge), v2 (preprocessed, 77.7%), v3 (tuned, 79.9%)

### `titanic_random_forest.py`

**Model:** Random Forest ensemble  
**Best configuration:** `n_estimators=500`, `max_depth=9`, `min_samples_split=2`, `max_features=sqrt`, `class_weight=None`  
**Selection method:** Two-stage GridSearchCV — Stage 1 broad pass (max_depth 6–9), Stage 2 focused ±1 around Stage 1 winner

**Key design decisions:**
- No feature scaling or log transforms — trees split on thresholds, not distances, making RF scale-invariant
- `oob_score=True` provides a free independent generalization estimate from bootstrap samples without a separate validation set
- Probability threshold sweep (0.35–0.50) applied post-training using `predict_proba` to optimize Survived recall without retraining
- `FamilyBand` categorical feature replaced raw `FamilySize` and `IsAlone` after v1 importance analysis showed a 4.5x importance gap between them

Random Forest outperforms SVM on overall accuracy and generalization. Both approaches are valid strategies for handling the 38/62% class imbalance and reflect fundamentally different model architectures reaching similar conclusions about the data.
